Everything you need

One client. Every mailbox.

Gmail-style organization on top of the accounts you already use, with the flexibility of a self-hosted tool.

Every account, one view

Gmail, Outlook, iCloud, Fastmail, Yahoo and custom domains side by side, with colored account labels and a shared address book.

Labels and filters

Create labels shared across accounts and apply them with filters that cover every folder. Word rules are re-evaluated once the body is indexed, forwarding aliases are read from the real headers, and conversations keep every label they carry. Each account's automatic label is an editable filter.

Fast, automatic sync

Folder lists open from a local D1 mirror while a resumable background sync keeps metadata and read state current. The optional cron worker checks each account on its own interval, from every minute to every 30 minutes, and also delivers background notifications.

Fast opens, optional archive

Recent bodies are cached briefly so opening a message does not wait for IMAP. Keep bodies on your provider or archive them to Cloudflare R2 or Google Drive.

HTML on your terms

HTML email is rendered in a sandboxed frame with scripts disabled. Remote images and tracking pixels stay blocked until you enable them for a message.

Inbox actions

Select one or many messages to delete, move between Inbox, Spam and Trash, or mark as spam. A dedicated Spam folder is included.

Send-only domains

Relay accounts for domains without SMTP, with SMTP2GO, Resend, Mailgun, Brevo, SendGrid, Mailjet, Postmark and Cloudflare Email Service support (experimental). Reply from any address on the relay's domain without an account per address.

Contacts, signatures and vacation responder

A structured address book with name, company, phone, address, extra emails and vCard 3.0/4.0 import/export; recipients become Other contacts automatically. Signatures and the vacation responder support rich text, shared or per account.

Write like Gmail

Rich-text composer with bold, lists, links and quotes, plus a plain-text fallback. The default format is saved per device, and Enter never sends a message by accident.

Privacy by default

Your mail stays yours.

WhelkMail reads from your provider. HTML is rendered in a sandboxed frame with scripts and forms disabled; remote images and tracking pixels stay blocked until you enable them for a message. A short-lived D1 cache keeps recent bodies for fast opens, and long-term archiving remains opt-in.

  • Sandboxed HTML with scripts blocked and remote images opt-in
  • Short-lived body cache with automatic cleanup
  • Credentials encrypted at rest with AES-256-GCM
  • Optional TOTP two-factor authentication
  • Server-side sessions, revocable on logout
  • Login and 2FA rate limiting per IP
  • One-time OAuth state and PKCE for Google and Microsoft
  • CSP, HSTS and strict security headers
Not a mail server

You keep using the providers you already trust. WhelkMail is the client.

Cloudflare or your own server

Deploy in minutes, not weekends.

Workers with D1, R2 and cloudflare:sockets by default. The same code runs on Pages, or in Docker with SQLite and any S3-compatible bucket. No mail server to patch.

01

Connect your mailboxes

Add Gmail, Outlook, iCloud, Yahoo or any IMAP/SMTP account. Credentials stay encrypted in your own D1 database.

02

Deploy to your account

Use the Deploy to Cloudflare button for Workers, follow the documentation for a manual Pages deployment, or run docker compose up on a VPS.

03

Optional: background scheduler

Folder opens already sync automatically. The Worker cron, the Pages cron worker, or the Docker scheduler handles periodic sync, notifications, forwarding, the vacation responder and provider cleanup.

Quick startbash
git clone https://github.com/WhelkMail/WhelkMail.git
cd WhelkMail
npm install
npx wrangler d1 create mail-client
# paste database_id into wrangler.jsonc
npm run db:init:workers:local
npm run dev:workers

Deployment options: the Deploy to Cloudflare button for Workers, a manual Cloudflare Pages deployment, or docker compose up -d --build in deploy/docker. See the documentation for platform-specific instructions, bindings, secrets and OAuth setup.
